# Подключение для агента

Сначала `node scripts/cloud.mjs check`. Рабочая авторизация workspace-mcp берётся из домашней папки текущего пользователя, только для dep6.2. Она не входит в пакет и не копируется между продавцами.

Fallback — Google Cloud CLI. Если не установлен, агент устанавливает его по официальному руководству: https://cloud.google.com/sdk/docs/install . Перед установкой проверить ОС и доступный менеджер пакетов. Пароли, выбор аккаунта и Google consent выполняет человек в открытом браузере.

После установки:

```sh
node scripts/cloud.mjs login
node scripts/cloud.mjs check
```

Login использует официальный `gcloud auth login dep6.2@bbooster.io --enable-gdrive-access --no-activate`: https://docs.cloud.google.com/sdk/gcloud/reference/auth/login . Авторизация не меняет основной аккаунт gcloud. Нужен разрешённый компанией доступ к dep6.2. Если компания не выдала продавцу этот доступ, не использовать личный аккаунт, не передавать refresh-token Сергея; рабочий Google-маршрут остаётся блокером. Локальная сборка доступна.

На Windows команды вызываются из Node и установленный gcloud должен быть в PATH; в свежем терминале PATH уже обновлён. macOS и Linux используют те же Node scripts.

Перезапуск после ошибки не создаёт второй файл. Для существующего ID export обязателен. Если нет доступа к папке, точная ссылка для администратора: https://drive.google.com/drive/folders/1kXTT8-O2vb8UpqdZEENyujUD3N2PP7R7 . Новые доступы не выдаются скриптом автоматически.

Google credentials никогда не сохраняются в папке проекта/скилла. Реестр и изображения доступны из установленного пакета даже без Google, поэтому их не нужно отдельно скачивать с личного компьютера Сергея.
