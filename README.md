# Итоги встречи · Business Booster

Приложите текст клиентской встречи в Codex или Claude Code. Скилл соберёт редактируемую презентацию, подберёт кейсы и загрузит **один Google Slides** в общую рабочую папку. После ручных правок обновляется та же ссылка.

## Начать

Передайте эту ссылку Codex Desktop/CLI или Claude Code вместе с запросом:

> Установи скилл «Итоги встречи» из https://github.com/dep62-byte/itogi-vstrechi. Скачай последний выпуск, распакуй его и прочитай README. Сам проверь окружение и установи необходимые зависимости и скилл в моём Codex. Подключи рабочий Google Диск по инструкции. Если требуется вход, открой авторизацию и попроси меня только подтвердить её. Не запрашивай пароли и не копируй чужие токены.

Репозиторий открытый: приглашение и аккаунт GitHub для скачивания не нужны. При ручной установке скачайте ZIP из [последнего выпуска](https://github.com/dep62-byte/itogi-vstrechi/releases/latest), распакуйте и откройте папку в Codex. Для Claude Code замените в запросе «в моём Codex» на «в моём Claude Code».

Агент выполняет `node scripts/install.mjs codex`. Для Claude Code — `node scripts/install.mjs claude`. Требуется Node.js 20+; агент может использовать runtime приложения. Затем откройте новую задачу, приложите транскрипт и напишите:

> Примени скилл «Итоги встречи». Имя клиента и дату возьми из приложенного текста; уточни только если они неоднозначны. Собери презентацию, выбери кейсы из комплекта, проверь условия и все слайды после загрузки. Верни одну ссылку Google Slides.

Для правки:

> Вот последняя презентация: [ссылка]. Сохрани мои ручные изменения. Измени: [что нужно]. Обнови этот же файл и проверь результат.

## Что уже внутри

- Правила фактов, условий, цен и запрет выдумывать обещания.
- Семь карточек кейсов: три с просмотренными оригиналами интерфейсов, четыре текстовые.
- Редактируемые макеты обложки, задач, кейса, таблицы и следующих шагов.
- Загрузка, обновление, экспорт, проверка структуры и защита от обновления непрочитанной облачной версии.
- Демонстрация на вымышленных задачах, тесты и проверка целостности изображений.

## Что нужно один раз

Для загрузки презентаций нужен разрешённый компанией вход в Google `dep6.2@bbooster.io`. Открытый доступ к скиллу не даёт доступа к рабочему Google Диску. Авторизоваться в браузере может только сам пользователь; установщик не получает ваш пароль.

Поддержан полный маршрут в **Codex Desktop/CLI и Claude Code** с исполнением команд и сетью. Веб-чат без исполнения кода полного маршрута не даёт. Установка и локальная сборка проверены на macOS; Windows/Linux предусмотрены кодом, но не прогонялись на компьютерах продавцов.

## Проверка и отправка

ИИ проверяет факты, собирает PPTX, экспортирует Google Slides, проверяет число страниц и редактируемый текст, затем смотрит все слайды. До визуальной проверки ссылка считается черновиком. Продавец проверяет имя, коммерческие условия и следующий шаг, после чего сам отправляет презентацию клиенту.

Одну встречу одновременно ведёт один продавец. Между проверкой версии и загрузкой нет транзакционной блокировки Google; не редактируйте презентацию параллельно с её обновлением агентом.

Исходные записи, транскрипты, клиентские файлы и токены **не загружать в GitHub**. Рабочая папка встречи находится отдельно от скилла. В открытый пакет включены только отобранные кейсы и проверенные изображения; публикация этого состава разрешена владельцем.

## Обновление скилла

Скачайте следующий выпуск и попросите Codex повторить установку. Управляемая предыдущая версия сохраняется в локальной резервной папке. Самодельная версия без метки установщика не перезаписывается. Условия и кейсы обновляются только вместе с выпуском; дата источников видна в `references/version.json`.
